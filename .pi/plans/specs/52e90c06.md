# Context

This spec is REQUIRED context-linked to PRD `8c37c573` (Realistic Apply Patch Upgrade). The implementation MUST preserve lifecycle control by user intent and policy flags.

# Technical design

## Architecture

The system MUST implement a deterministic pipeline with explicit phase boundaries:

1. Parse
2. Normalize
3. Preflight plan
4. Commit

The pipeline MUST support unified diff as the only execution input mode.

- Unified Diff mode (canonical execution input)

All commit behavior MUST route through the same execution core.

## Phase model

### Parse

The parser MUST produce a typed AST per file patch containing:

- file headers
- optional extended headers
- hunk headers
- hunk lines
- EOF newline markers

Unsupported syntactic forms MUST fail with `PatchParseError`.

### Normalize

Normalization MUST be policy-driven and non-lossy by default:

- line endings: `preserve | lf | crlf`
- whitespace matching mode: `strict | tolerant`

Normalization MUST NOT silently alter user-authored content intent.

### Preflight plan

Preflight MUST run with zero filesystem mutation and return a full operation plan.

Planner responsibilities:

- classify ops: `create | edit | move | delete`
- resolve per-hunk anchors
- detect overlaps and ambiguity
- enforce path sandbox policy
- detect unsupported features by flags
- compute post-state snapshots in memory

### Commit

Commit MUST be atomic in strict mode:

- stage temp outputs
- perform deterministic op ordering
- finalize writes and renames atomically where possible
- rollback on any error

# Interfaces

## Public request schema

```ts
type Mode = "unified";
type LineEnding = "preserve" | "lf" | "crlf";

interface ApplyPatchRequest {
  mode: Mode;
  patch: string;
  options: {
    dryRun: boolean;
    strict: boolean;
    offsetWindow: number;
    fuzz: number;
    allowCreate: boolean;
    allowEdit: boolean;
    allowMove: boolean;
    allowDelete: boolean;
    allowCopy: boolean;
    allowMode: boolean;
    allowBinary: boolean;
    lineEnding: LineEnding;
    sandboxRoot: string;
    maxFiles: number;
    maxChangedLines: number;
  };
}
```

Request invariants:

- `mode=unified` MUST provide `patch`.
- `dryRun=true` MUST skip commit phase.

## Public response schema

```ts
type Phase = "parse" | "preflight" | "commit";
type Op = "create" | "edit" | "move" | "delete";
type Item = "applied" | "already_applied" | "rejected";

interface ApplyPatchResponse {
  ok: boolean;
  phase: Phase;
  summary: {
    files: number;
    hunks: number;
    additions: number;
    deletions: number;
    alreadyApplied: number;
  };
  files: Array<{
    pathOld: string;
    pathNew: string;
    operation: Op;
    status: Item;
    hunks: Array<{
      index: number;
      status: Item;
      relocatedBy: number;
      fuzzUsed: number;
    }>;
  }>;
  errors: Array<{
    code: string;
    message: string;
    path: string;
    hunk: number | null;
    expected: string | null;
    actual: string | null;
    candidates: string[];
    remedy: string;
  }>;
}
```

# Constraints

- The system MUST fail fast on invalid input, unsupported features, and ambiguity.
- The system MUST NOT perform best-effort silent writes.
- The system MUST preserve create, edit, move, and delete parity with existing behavior.
- The system MUST keep lifecycle user-controlled via explicit options and dry-run.
- The system MUST NOT start commit if parse or preflight fails.

# Edge cases

1. Repeated context blocks producing multiple anchor candidates.
2. Mixed line endings in target files.
3. Missing newline at EOF markers.
4. Rename target collisions.
5. Already-deleted file in idempotent retry mode.
6. Patch headers and hunk counts mismatch.
7. Unsupported binary patch blocks when `allowBinary=false`.
8. Large patch budgets exceeding `maxFiles` or `maxChangedLines`.

Expected behavior for each edge case MUST be deterministic and typed.

# Deterministic verification criteria

1. Same input, same filesystem baseline, same options MUST produce identical plan and output fields.
2. Ambiguous anchor detection MUST return identical candidate ordering and error code.
3. `dryRun=true` MUST produce no writes under all paths.
4. `strict=true` MUST guarantee all-or-nothing persistence.
5. `already_applied` classification MUST be stable across retries.
6. Parse and healing output MUST be deterministic for identical source and options.
